# v1.4 Release Notes (Draft)

Status: gate/catalog foundation present; publication workloads and dedicated
measurements pending.

## Additions

- Workload catalog for passthrough, transform-heavy, fan-out, and
  aggregation-heavy profiles at 1 KiB and 10 KiB.
- Fail-closed performance release evaluator for publication eligibility, exact
  accounting, errors, repetitions, variance, throughput, p99 latency, and RSS.
- Machine-readable normalized record of the 2026-07-25 AWS passthrough
  baseline.
- Named, owned, milestone-bound exception format.

## Behavior and migration

- Shared-runner measurements remain diagnostic and non-blocking.
- Release claims require dedicated-hardware evidence.
- A missing measurement fails the gate; it is never treated as unchanged.
- Current documentation may cite only the canonical workload result.

## Known limitations

- The canonical passthrough baseline lacks p99 latency and exact 1 KiB payload
  normalization, so it cannot pass the new gate without a documented exception.
- The existing runner still executes the passthrough profile only.
- New dedicated transform-heavy, fan-out, aggregation-heavy, 10 KiB, and
  processing/delivery matrix results do not yet exist.

## Rollback

Performance tooling does not change runtime compatibility. Revert the gate and
catalog only with the associated documentation; do not restore superseded
comparative claims or generated runtime artifacts.

## Exceptions

An exception JSON entry must include `check`, `owner`, `reason`, and
`removal_milestone`. Release notes must repeat every active exception.
