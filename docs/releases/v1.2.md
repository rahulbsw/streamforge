# v1.2 Release Notes (Draft)

Status: implementation present; live Kafka/Prometheus gates pending.

## Additions

- `/ready` reports structured Kafka-backed readiness with HTTP 200 or 503.
- `/health` remains backward compatible and returns literal `OK`.
- `streamforge_build_info` and `streamforge_ready` are exported.
- Bounded UDF invocation, duration, byte-size, active-invocation, and startup
  compilation metrics remain registered in the same idempotent registry.
- `STREAMFORGE_LOG_FORMAT=text|json` is additive; `RUST_LOG` remains supported.
- Helm includes a metrics Service, ServiceMonitor, PrometheusRule, recording
  rules, alerts, and a Grafana dashboard.
- PrometheusRule and ServiceMonitor labels are configurable for selector-based
  Prometheus installations.

## Behavior and migration

- Kubernetes pipeline pods expose port 9090, use `/ready` for readiness and
  `/health` for liveness, and default to JSON logs.
- The configured `observability.metrics_path` is now honored and validated.
- Operational logs omit payloads, credentials, keys, filter expressions, and
  transform expressions.
- Existing metric names and `/health` clients remain compatible.

## Known limitations

- The metrics Service and `PrometheusRule` are installed whenever
  `monitoring.enabled=true`; ServiceMonitor and dashboard creation use child
  gates.
- PromQL has passed Helm rendering and YAML parsing but still requires
  `promtool` and live Prometheus validation.
- Live Kafka failure/recovery and dashboard/alert smoke tests remain release
  gates.

## Rollback

Roll back all component/chart versions together. Existing `/health` probes
remain valid. Remove new monitoring resources by rolling back or uninstalling
the chart; do not delete shared Prometheus infrastructure.

## Exceptions

No release exception is accepted for the missing live smoke evidence; tagging
remains blocked until it is collected.
