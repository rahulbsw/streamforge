# v1.3 Release Notes (Draft)

Status: implementation present; browser and Kubernetes integration gates
pending.

## Additions

- Six-step multi-destination onboarding with templates, source, destinations,
  processing, reliability/resources, validation, and review.
- YAML import/export, current DSL expressions, secret references, retry/DLQ,
  and resource settings.
- Structured CRD validation:
  `streamforge-validate --input-format pipeline-crd --output json`.
- Kubernetes server-side dry-run before create.
- Pipeline summary, metrics, events, and bounded log APIs and detail views.
- Admin/viewer authorization and explicit production authentication.

## Behavior and migration

- `StreamforgePipeline` remains `streamforge.io/v1alpha1`.
- Additive fields:
  `spec.retry.{maxAttempts,initialDelayMs,maxDelayMs,multiplier}` and
  `spec.dlq.{enabled,topic,includeHeaders,maxDlqRetries}`.
- Existing additive `spec.udfs` module/runtime definitions and destination UDF
  bindings remain supported by the shared operator projection.
- Structured validator diagnostics use the canonical `field` key. CRD
  validation checks artifact paths/names, runtime limits, digest uniqueness,
  binding existence, and binding world before Kubernetes creation.
- All destinations in one resource must currently share one target broker set.
- All destinations also share one target security configuration.
- Production UI deployments must provide configured users and JWT secrets.
- The wizard uses `spec.appid` as the consumer identity and does not expose the
  compatibility-only, runtime-ignored `spec.source.groupId` field.
- Source and target Kubernetes Secret references are converted into separate
  file-backed engine security settings; inline credential values are rejected.
- The unsupported per-destination `compression` CRD/UI field was removed.
  Configure the engine's supported global compression policy in direct runtime
  configuration when needed.

## Known limitations

- The UI remains Kubernetes/operator-backed and does not manage local
  standalone processes.
- Published multi-architecture image, Playwright, and kind/minikube integration
  gates remain pending. The local Linux image and bundled validator smoke pass.
- Prometheus metrics support only the enumerated `15m`, `1h`, `6h`, and `24h`
  windows and predefined server queries.

## Rollback

Export pipeline YAML before rollback. Roll back the UI, operator, engine, and
chart together. The additive v1alpha1 fields can remain stored but should be
removed from manifests if rolling back to an operator that does not recognize
them.

## Exceptions

No exception is accepted for authorization, server-side dry-run, or
validator-image integration. The development-only Next.js 15 lint-plugin
exception described in the v1.1 notes remains owned by `track/ui` with removal
milestone `v1.4`; production dependencies contain no high-severity audit
finding.
