# v1.1 Release Notes (Draft)

Status: implementation present; release artifact and live smoke gates pending.

## Additions

- Published archives contain `streamforge` and `streamforge-validate`.
- Linux amd64/arm64 and macOS arm64 release jobs create checksums, SPDX SBOMs,
  and provenance attestations.
- Engine, operator, and UI images publish at one exact version.
- The Helm chart publishes as an OCI artifact with matching `appVersion`.
- Root, operator, UI, internal config-model, chart, and quickstart versions are
  synchronized and checked against the release tag.
- `scripts/quickstart.sh up|verify|down` supports Docker and Podman and checks a
  real replicated record.
- Release smoke validation verifies digest-pinned WebAssembly UDF startup.
- Container preflight builds and smoke-tests engine, operator, and UI images
  before any release artifact is published.
- Release base images are pinned to immutable multi-architecture digests.
- Engine images and operator-managed pipeline pods use UID/GID `65532`; Kafka
  Secrets are group-readable only and mounted read-only.

## Behavior and migration

- Release workflows no longer publish `latest`; pin the exact version.
- Production UI installation requires an existing Secret with the configured
  JWT-signing and users-JSON keys. Generated credentials are limited to
  explicit Helm development mode.
- The UI image builds `streamforge-validate` against its own Debian runtime
  instead of copying an Ubuntu-built dynamically linked binary.
- Helm defaults are passed to the operator through explicit environment
  fields; no inert defaults ConfigMap or no-op values remain.
- Replace obsolete local install scripts and duplicated deployment examples
  with the quickstart or published-artifact paths.

## Known limitations

- Real downloaded-artifact, registry, Docker/Podman, kind/minikube, and cleanup
  smoke gates must pass before tagging.
- Supported artifacts are not available until the release workflow publishes
  this version.

## Rollback

Pin the prior engine, operator, UI, and chart versions together. Run
`scripts/quickstart.sh down` for local cleanup, or use Helm rollback/uninstall
for Kubernetes. Preserve the previous UI JWT Secret when rolling back.

## Exceptions

The ESLint 9 development-only plugin chain is still reported by the full
`npm audit` because Next.js 15 plugins require `minimatch` 3.x, which has no
patched compatible release. Production dependencies pass
`npm audit --omit=dev --audit-level=high`; the newer minimatch/brace-expansion
path is pinned to patched releases. Owner: `track/ui`. Removal milestone:
`v1.4`, with migration from the legacy-compatible Next.js lint plugin graph.
This exception does not cover runtime dependencies or production image
contents.
