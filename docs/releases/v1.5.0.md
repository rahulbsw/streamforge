# StreamForge v1.5.0 release notes

Status: release candidate. GitHub Release assets, registry images, and the
OCI Helm chart are available after publication. See the
[roadmap](https://github.com/rahulbsw/streamforge/blob/main/ROADMAP.md) for release gates and
[implementation status](https://github.com/rahulbsw/streamforge/blob/main/docs/IMPLEMENTATION_STATUS.md)
for verification evidence.

This is the next release after v1.0.0. It combines the implemented work from
the unpublished v1.1 through v1.4 planning milestones.

## What changed

- **Installation.** Release archives target Linux amd64, Linux arm64, and
  macOS arm64 and include `streamforge` and `streamforge-validate`. Publication
  adds checksums, SPDX SBOMs, and provenance. The engine, operator, UI images,
  and OCI Helm chart use the same exact version. The Docker and Podman
  quickstart verifies a replicated record and removes its own resources.
  The engine image builds on Wolfi so its native libraries match the runtime.
- **WebAssembly UDFs.** Run opt-in filters and transforms per destination.
  Modules are digest pinned, loaded at startup, and run with bounded resources
  and an empty host linker. The guest SDK and WIT ABI are versioned.
- **Observability.** Structured `/ready` reports Kafka readiness. Existing
  `/health` checks remain compatible. The metrics catalog covers build,
  readiness, and UDF execution. Helm can install Prometheus rules,
  ServiceMonitor, and a Grafana dashboard. Kubernetes pipeline pods default
  to JSON logs.
- **Kubernetes UI and operator.** Pipeline onboarding supports multiple
  destinations, YAML import/export, field-specific validation, and server-side
  dry-run. The UI adds status, metrics, events, and bounded log views with
  viewer/admin permissions. The operator reports a workload-backed `Ready`
  condition and owns the generated resources for cleanup.
- **Performance evidence.** The workload catalog and evaluator check
  accounting, errors, throughput, p99, RSS, repetitions, and hardware
  evidence before a benchmark result qualifies for publication.
- **Security.** Helm production UI deployments require explicit authentication
  secrets. Login attempts have a process-local limiter. Pipeline inputs use
  read-only Kubernetes Secret projections for credentials. Wasmtime 36.0.21,
  libz-sys 1.1.33, and url 2.5.9 address the five findings reported by the
  merged RustSec audit fix.

## Upgrade from v1.0.0

1. Back up pipeline YAML and environment-specific configuration. For
   Kubernetes, retain the current chart values and the UI's signing/user
   Secret. Pin all new artifacts to `1.5.0` once they are published.
2. Validate existing configurations with the matching `streamforge-validate`
   binary. For a pipeline resource, use `--input-format pipeline-crd --output
   json`. The CRD remains `streamforge.io/v1alpha1`, with additive retry, DLQ,
   and UDF fields. Use Secret references for Kafka credentials. For direct
   engine deployments, use the global compression setting.
3. Configure the operator and optional UI for the same watched namespace.
   Supply the UI signing and users Secret for production. Public or replicated
   UI deployments require a trusted ingress-wide or shared limiter.
4. Check readiness, record delivery, and monitoring before moving production
   traffic. The engine honors `observability.metrics_path`. Use `/ready` for
   readiness and `/health` for liveness.

See the [deployment guide](../DEPLOYMENT.md),
[Kubernetes guide](../KUBERNETES.md), and
[observability quickstart](../OBSERVABILITY_QUICKSTART.md).

## Limitations and outstanding evidence

- Destinations in one Kubernetes pipeline share a target broker set and target
  security configuration. The UI manages Kubernetes resources and exposes
  predefined metrics queries with fixed time windows.
- The WebAssembly runtime is stateless. Module hot reload, network loading, and
  WASI imports are outside this release.
- Candidate preflight can test archives, local images, and a chart package.
  Published archive, registry, multi-architecture, OCI chart, and clean-host
  Docker/Podman checks require published artifacts.
- Live Kafka recovery, PromQL and monitoring signal validation, and full
  Playwright coverage against kind/minikube remain outstanding.
- The historical passthrough baseline lacks p99 and exact 1 KiB normalization.
  Dedicated-hardware results for the remaining workload matrix are still
  needed. The release carries no new capacity or throughput claim.

## Rollback

Roll back engine, operator, UI, and chart as a compatible set. Use the
previously deployed, pinned artifacts and chart values. Preserve TLS/SASL and
UI authentication Secrets. Restore exported pipeline manifests or remove
additive fields unsupported by the previous deployment. For the local demo,
run `scripts/quickstart.sh down` to remove its resources.

## Exceptions

The development-only Next.js lint-plugin compatibility exception is owned by
`track/ui`. Remove it when migrating away from the legacy lint plugin chain.
The version jump leaves that follow-up open. The exception does not cover
production dependencies or image contents. Missing release evidence remains
open in the owning roadmap track.
